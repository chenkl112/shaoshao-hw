# 本车 0x81 XY 坐标与导航接入

当前按用户选择，**下位机 V2 保持不改**；只按上游已有的 `0x01`、`0x80`、`0x81` 接收。
不要求或等待 `0x82`，也不要求上传云台相对底盘编码器角。

上游协议文档描述 `0x81` 的 XY 为底盘本体速度；本车用户确认当前固件输出的是云台坐标系/世界系 XY，
且云台与雷达固定在同一方向。因此本机运行配置使用 `feedback_frame: map`。这是本车固件语义，
不修改上游协议文档或 MCU。

上位机只用 XY 判定速度反馈有效性、显示速度和提供导航闭环，不依赖 omega/yaw。XY 单位 m/s、不乘倍率；
无效或超过 150 ms 的样本不发布，也不伪装成零速。导航桥用该样本时间戳查询 `map -> navcar_center`，
将世界 XY 旋回导航控制器的本体轴。TF 不可用、定位未就绪或反馈超时，导航控制器保持停止。
接口 `ChassisFeedback` 仍要求角速度和控制允许字段；这里的角速度 0 是未测量占位，
`control_allowed` 表示上位机样本通过 XY/新鲜度检查，不代表 MCU 回报了 UART1 控制授权。

本仓库曾记录的 `0x82` 扩展与 C serializer 属于试验草案，不属于 Navcar 上游协议；实车配置不启用。
不得因为接收到未知帧而改变 `0x81` 解释。

# 底盘实测速度接入与可选扩展

上位机依据 Li-chee/Navcar-Comm-Protocol 提交
`43333c533538490c1e2262a63a004cde088d7f79` 的 V2 文档接入。
现有 `0x01`、`0x80`、`0x81` 帧不变，线格式 VERSION 仍是 1。
配置 `state_semantics: wheel_velocity_v2` 显式选择新状态语义；速度倍率必须全部为 1。

## 已支持的现有固件

`0x81` 的四个 float32 为底盘前向 vy、底盘右向 vx、底盘逆时针角速度 rot、惯导实测云台 yaw（度）。
前两项单位 m/s，rot 单位 rad/s。它们是轮速反解值，有打滑误差，不是独立对地测速。
NaN 保留为无效测量，不替换为零，不覆盖上一帧继续使用。
目标 yaw 与实测 yaw 分开保存，仅服务刚接入时用实测角初始化保持目标。
按照 V2 文档，控制 rot 正值直接表示逆时针，不再沿用旧客户端的取反。

8081 `/api/state` 的 `feedback_measurements` 返回实测速度，`feedback_targets` 在 V2 下为 null。
ROS `/navcar/chassis_velocity` 为 `geometry_msgs/TwistStamped`，frame_id=`navcar_chassis`：
linear.x 向底盘前，linear.y 向底盘左，angular.z 为底盘逆时针角速度。
无效或过期时不发布伪造零速；消费者必须检查时间戳及 `/navcar/chassis_feedback/status`。

现有 `0x81` 没有相对编码器角、硬件授权、独立测量计数与采样时间。惯导启动参考 yaw 不是云台相对底盘角；
ACK 成功不是控制授权；状态帧头序号也不是测量计数。上位机只按接收时间对 XY 做 150 ms 新鲜度限制。

## 兼容旧草案：0x82 revision 1（不是当前方案的要求）

保留原 `0x81`，增加 `0x82`，约 100 Hz，在同一轮测量/控制周期取快照发送。
每帧总长 46，LENGTH=36（`24 00`），CRC16/MODBUS 与现有协议相同。
帧头 sequence 仍放最近接受的控制序号，只用于诊断；不影响 ACK 同步。

Payload 对应 Python `struct.pack('<BBHIII5f', ...)`：

| payload 偏移 | 类型 | 字段 |
|---:|---|---|
| 0 | uint8 | 扩展 revision，固定 1 |
| 1 | uint8 | flags，定义见下 |
| 2 | uint16 | reserved，必须 0 |
| 4 | uint32 | sample_sequence，每次新的实测快照加一，允许自然回绕 |
| 8 | uint32 | measurement_ms，测量快照的 MCU 单调毫秒时钟，允许自然回绕 |
| 12 | uint32 | authority_epoch，每次控制源切换、UART1 授权禁用/恢复均加一 |
| 16 | float32 | vy_body_mps：底盘前向实测速度 |
| 20 | float32 | vx_body_mps：底盘右向实测速度 |
| 24 | float32 | chassis_ccw_radps：底盘实测逆时针角速度 |
| 28 | float32 | gimbal_relative_ccw_rad：云台/雷达朝向减底盘朝向，CCW 为正，归一化 ±π |
| 32 | float32 | imu_yaw_deg：惯导实测启动参考 yaw，度，与 `0x81` 相同 |

flags：bit0=`UART1_ALLOWED`；bit1=`WHEELS_VALID`；bit2=`GIMBAL_VALID`；bit3=`IMU_YAW_VALID`；bit4–7=0。

- bit0 必须来自实际模式仲裁和电机输出条件：UART1 被选中、输出允许才为 1。
  遥控器掉线但固件实际选择 UART1 时可以为 1；不能按“收到命令/ACK=0”推断。
- bit1 仅在全部四轮反馈新鲜（≤100ms）、有限且解算成功时为 1。
- bit2 仅在 yaw 编码器在线且新鲜（≤100ms）、相对角换算有效时为 1。
  使用实际零位和编码器方向换算；禁止用惯导启动 yaw 或 yaw 目标冒充。
- bit3 仅在惯导实测 yaw 有效且新鲜时为 1。此绝对参考角不参与相对坐标转换。
- UART1→遥控器→UART1 即使发生在两次发送之间，也必须让 epoch 累加两次。
  MCU 重启导致计数/时钟倒退时，上位机锁定停止，需要重启 8081 重新同步。
- 速度参考点是 yaw 轴所在车体中心。当前实车配置 yaw 轴位于底盘中心；若安装改变，
  需要先从轮速解算中心换算到 yaw 轴，不能仅改 frame 名称。
- 发送函数使用独立、生命周期足够长的 UART/DMA 缓冲区，与 ACK、0x81 共用发送队列；
  不得并发覆盖同一个 DMA 缓冲区。这里没有下位机源码，未实现或烧录 MCU 端传输。

`navcar_feedback_v2.h` 提供无 HAL 依赖的 C 打包函数，只负责序列化及 CRC。
在现有运动任务快照处填写真实数据、有效标志和仲裁 epoch 后，将返回的 46 字节交给已有 UART 发送队列。
继续发送原 `0x81`；上位机不发额外探测命令。

## 上位机转换与门控

设 a 为云台相对底盘实测 CCW 角。底盘 ROS 速度为 `(vy_body, -vx_body)`：

```text
v_forward_lidar = cos(a)*vy_body - sin(a)*vx_body
v_left_lidar    = -sin(a)*vy_body - cos(a)*vx_body
```

转换结果进入 `/hw/chassis_feedback`，frame_id=`navcar_center`，底盘 omega 保持为实测底盘角速度。
上位机以 MCU 采样间隔和接收时间对齐 ROS 时钟；最大接受延迟 150ms。
此方式不能测出首次帧的绝对单向传输延迟，要求 MCU 只发送当前快照、不回放历史测量。
重复测量不刷新时间，积压帧不重打“当前时间”冒充新鲜数据。
扩展无效、过期或授权切换会撤销导航 lease；恢复后旧 lease 不会重新生效。
自动导航需要定位、路径和控制器等其他条件同样就绪；速度反馈就绪并不保证导航成功。

实车配置 `feedback_protocol: navcar_uart1_v2`、`feedback_frame: map`：手动控制、V2 世界系 XY 显示，
以及由定位 TF 转换后的自动导航速度反馈可用。UART 协议不提供 MCU 控制授权状态；本方案不把该状态伪报为硬件测量。
默认待机、小陀螺关闭；平移上限仍为 0.3m/s，小陀螺上限仍为 6rad/s。
