# 持续导航直到到达目标

已接受的导航目标在当前监督进程中持续保留，没有任务总时长或最大重试次数。临时堵路、MPC 无可行轨迹、路径规划失败、动作拒绝、短时定位/反馈/串口不可用，都先禁用运动输出，再等待条件恢复并重新规划同一个 XY 目标。

- HW 规划/恢复接入后，Nav2 `failure_tolerance=0`；连续 3 拍碰撞拒绝和 6 s 无进展由 C++ 控制器管理。显式失败结束单次尝试，保留上层目标。
- 执行失败后约等待 0.5 s 再尝试规划。没有通路则继续停车重试，不会放松碰撞或速度约束。
- 一个动作发送或规划请求仍有独立超时；取消响应超过 3 s 后废弃该动作代次。迟到的响应不能重新启动旧动作或完成新动作。
- 网页用 `waiting` 表示停车等待，`goal_pending` 表示目标仍未完成，`retry_count` 记录重试。等待和自动取消过程中都可显式取消任务，禁止无意覆盖目标。
- 到达目标、实际平移速度低于停止阈值后结束任务并释放租约。当前到达阈值为 XY 误差 0.03 m、实际平移速度 0.03 m/s；不要求底盘转向目标朝向。
- 人工取消、人工控制权变更、硬件明确撤销授权、切换模式会撤销目标。地图版本变化也会终止旧坐标目标，并要求重新进入导航加载地图。
- 短时反馈过期仅暂停；恢复时仍须满足同一硬件授权代次、有效实际速度、定位和障碍数据的新鲜度要求。硬件明确禁止控制之后重新允许，不会自动恢复旧任务。

原生状态机回归模拟了连续 15 次控制失败并重试、超过原进展超时时长后仍持有目标、最终成功、等待中取消、反馈暂失与授权撤销的区别、取消响应超时、迟到回调、地图暂不可用和地图变更。

真实 ROS Jazzy 验收使用合成房间和 PTY MCU：故意让障碍预测失效，触发 Nav2 Controller patience exceeded / Goal failed，确认目标继续保留、串口输出零速。恢复正常输入后，同一个原目标重新规划并到达、停车；另一次在等待中取消，恢复数据后确认没有重新启动。还覆盖定位恢复、人工接管和模式切换参数重新加载。

结果见 `2026-10-23-persistent-goal.json`。合成位姿误差不代表实车精度。本功能不包含断电或监督进程重启后的任务持久化；重启后需重新下发目标。实际车辆仍需按已确认的电控协议和反馈接入后验证。

后续 HW 原始规划与恢复接入见 [HW 规划与脱困](hw-planning-recovery.md)；本页原验收 JSON 记录的是接入前结果。
