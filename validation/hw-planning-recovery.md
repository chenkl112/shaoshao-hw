# HW 原始规划与脱困的全向适配

参考版本为 `Polyacetone/HWSentryNav26@f5f941288197e14c867d711a4c4cd85bfd7a3194`。
生产路径全部是 C++；FAST-LIO、小陀螺独立控制、电控负责单轮分配的约定保持不变。

## 全局规划

Nav2 `GridBased` 已从 NavFn 切换到本地 `hw_omni_controller::Planner`：
空间 A* → LOS 参考路径与引导时标 → 自由空间走廊 → 走廊 Kino A* → MINCO 连续曲线 → 弧长速度剖面。
这些阶段使用 HW 原始 C++ 源码，不是用 NavFn 路径平滑代替。Nav2 负责异步动作、生命周期和任务接口。
独立规划线程进行搜索和优化；取消在搜索/L-BFGS 内协作检查。

Kino 的航向与曲率表示平移速度的方向，用于构造平滑几何种子，不代表雷达或底盘的航向。
起点以实际地图系速度方向为主根，静止时朝目标构造主根，并允许 16 个无朝向偏置的根；
实际控制仍输出雷达坐标的 vx/vy，angular.z=0。保留 HW 几何塑形边界会使路线偏好圆滑转弯，
全向车允许的原地改变平移方向并未作为额外 Kino 原语加入。

平地场景方向场为零，不启用轮腿台阶、助跑、飞坡和地形模式。当前全局 Nav2 地图融合静态地图与实时占据，
不同于 HW 只让地形相关动态障碍改变全局拓扑的分层地图；局部仍保留逐时刻动态障碍预测。
未知区按整车圆形包络扩张，曲线发布前按不超过半格的间距做车体/边界复核。
不把目标挪到附近空位；不可达目标保留并等待。

`/hw/planned_trajectory` 携带原始 MINCO 五次系数与 HW 速度剖面；控制器检查尺寸、数值、速度边界、终点，
只接纳与当前 Nav2 path 时间戳和全部路径点一致的快照。旧快照无法给新任务授权。
控制器用 HW RouteTracker 估计有向弧长，按 HW 速度剖面生成 MPC 参考；
速度、加速度与整车响应约束最终由全向 MPC 硬验收。

## 任务、监控与恢复

- 规划失败：保留原目标，0.5 s 冷却后重试；无任务总超时和最大重试次数。
- MPC 无安全碰撞轨迹：当拍零速，连续 3 拍拒绝后立即请求重规划；安全轨迹会清零连续计数。
- 跟踪丢失、当前位置到参考点的投影连线被阻断：撤销当前路径，停车，重新规划原目标。
- 跟随 6 s 没有跨过新的 0.1 m 弧长进度格，或指令速度达到门槛、2 s 位移不超过 0.2 m：进入 STUCK_REVERSE。
- 反向退让沿受阻前的平移反方向，不依赖旋转中的底盘前后轴。默认参考速度 min(0.2 m/s, 全局限速的一半)，目标退让 0.35 m，3 s 超时。
- 退让结束时若当前位置危险，进入 HAZARD_RECOVERY；否则重新规划原目标。超时只结束本次退让，不会取消目标。
- 危险区恢复复用 HW 极坐标搜索：半径 0.5–1.5 m、5 层半径、72 个方向，按沿途障碍代价积分选择安全点；4 s 重新搜索，安全区保持 1 s 后重新规划。
- 无安全点或安全轨迹：零速等待。恢复阶段也必须满足定位、实测速度、授权、预测新鲜度和独立刹停通路检查。

HW 原版退让直接发负速度，本车的退让与安全点运动均经过全向 MPC、合速度/加速度/jerk 限制和 50 Hz 独立安全转发。
当前位置已侵入硬障碍、未知区域或无法认证刹停通路时不强行驶出。
危险代价阈值沿用 HW 的 30/255，安全阈值为 5/255；需要结合实车地图膨胀层实测调整。

行为树采用一次计算路径、持续 FollowPath 的 Sequence；失效事件才重规划，避免固定 1 Hz 换路径清掉无进展计时。
Nav2 使用 `RecoveryProgressChecker` 将进度处理交给 HW，`failure_tolerance=0` 让显式重规划事件立即结束一次动作。
外层继续持有目标。取消、人工接管、授权撤销、模式切换、地图版本变化会终止任务，恢复结束不能重启这些旧目标。

## 验证

`hw_omni_controller/test/test_navigation.cpp` 覆盖完整管线、绕墙、无路、未知目标、搜索取消、
轨迹往返与过期身份、厘米级目标的加减速节点、圆形未知区边界、速度剖面、6 s 无进展、2 s 物理卡住、退让完成/超时、安全点搜索/安全保持、连续碰撞计数。
`validation/ros_integration.py` 运行实际 ROS Jazzy、Nav2 插件、全向 MPC、Web 任务与 PTY MCU；
模拟传感器/实际速度，注入预测故障、物理阻挡与定位故障，并验证原目标续行、人工接管、取消和配置重载。
结果与限制以本次验收 JSON 为准；合成场景结果不是实车精度或实车脱困成功率。
