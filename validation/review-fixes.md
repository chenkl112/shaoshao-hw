# C++ 运行链路审查修复

对应 c603d61 的八项审查问题，生产运行节点仍使用 C++，网页前端使用 JavaScript。

| 问题 | 修复行为 | 验证 |
|---|---|---|
| 中心格检查遗漏未知区域下的车身 | MPC 和独立 relay 检查圆形整车足迹；地图边界视为不可用，沿轨迹的检查加入步距余量 | 已知中心、未知车身边缘、窄已知通道和地图边界的原生回归 |
| 64 个页面会话后拒绝停止 | 会话按活动时间回收并淘汰旧记录；合法停止不读取无关速度字段，先撤销导航控制权 | 65 个页面控制请求，导航中停止，无效 strength/spin_rate，不超过 64 个保留会话 |
| 自动恢复异常终止监督进程 | 规划/控制权申请失败保留目标并退避 5 s；异步拒绝也保留目标；取消失败仍禁用输出；执行器线程设异常边界 | 规划失败、申请租约失败、异步拒绝、取消异常和后续成功重试 |
| 退化限速与目标历史冲突 | 当前目标或实际速度高于新限速时进入零速等待；实际速度下降后重建目标历史，保留路径和控制权 | 0.3 → 0.05 m/s 限速状态判定、等待实际速度、恢复低速 MPC |
| 整数高度被序列化成 ROS integer | 用保留浮点类型的统一转换生成高度、分辨率及外参 | 高度 2.0 的配置回归和真实 FAST-LIO 建图启动 |
| 新 PCD 和旧 PNG/YAML 混用 | 保存期间暂停预览落盘；`/hw/export_grid` 从保存的 PCD 同步重建二维资产；新地图记录 `bundle.json`，导航核验三类资产哈希 | 旧二维地图被拒绝、真实保存服务、文件哈希、资产篡改被拒绝 |
| 超时导航租约永久占用 | 0.2 s 运动看门狗之外，0.5 s 未收到有效新指令即撤销租约；relay 不无限用零速替失联任务续租 | MCU 通讯正常时孤立租约过期、新租约重新申请、旧租约迟到指令被拒绝 |
| 模式切换使用旧配置缓存 | 进入模式时校验并写入 `active_robot.yaml`；栈、定位、任务桥使用同一快照；新任务申请控制权时更新串口导航限速 | 限速 0.25 → 0.15 m/s、tau_x 0.4 s，切换后检查生成配置、UART 限速和新目标到达 |

控制权申请还携带已知的人工接管代次。人工停止之后到达的旧申请会被拒绝；监督进程丢弃早于租约变更的串口轮询结果，避免把新任务错误地判成失去控制权。

正常运动仍遵守 MPC 的目标速度、加速度、jerk 及碰撞约束。降低限速时的零速等待属于安全停车状态，优先于普通运动的目标变化约束；实际机械制动性能仍需实测。已有未带 bundle.json 的地图保留兼容，新保存地图采用完整资产校验。

结果记录见 `2026-10-23-review-fixes.json`。验证使用隔离 ROS Jazzy、合成点云/IMU 和 PTY MCU，没有接入真实雷达或电机。新电控字节协议仍按原计划保留接口。
