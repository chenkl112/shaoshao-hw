# UART1 小电脑接入协议V2



更新：将MCU返回值改为根据轮速与机械结构解算的理论值。

小电脑下发四个控制目标，MCU 返回 ACK，并以约 100Hz 回传**四轮实测轮速反解的车体速度及惯导实测云台角度**。状态发送位于每轮运动计算之后，不再回显 UART1 候选指令。

帧格式、波特率、类型、序号、CRC、ACK 和状态帧长度保持原样；`0x81` 的字段含义已更新。旧客户端可以继续组帧，但必须更新状态字段的坐标系、单位和有效性处理，不能再把状态值与下发目标直接作相等比较。

## 1. 接线与接入流程

| 项目 | 配置 |
|---|---|
| 电气接口 | 3.3V TTL，全双工，共地 |
| 串口配置 | 2000000 bit/s，8 数据位，无校验，1 停止位，无流控 |
| 小电脑 TX → MCU RX | PB7，USART1_RX |
| 小电脑 RX ← MCU TX | PA9，USART1_TX |
| 板上标识 | 本车接口丝印为 UART2，固件使用 USART1；以 PB7/PA9 引脚为准 |
| 编码 | 原始二进制；多字节整数和 IEEE754 float32 均为小端序 |

接入步骤：

1. 打开串口、清除旧接收缓存，等待 MCU 初始化完成并收到有效状态帧 `0x81`。
2. 读取状态帧序号 `S`，第一条控制命令使用 `(S + 1) & 0xFFFF`。
3. 发送控制帧，等待相同序号的 ACK。状态码为 `0` 或 `1` 时结束本次等待。
4. 正常情况下约每 **20ms** 下发一条新命令；即使四个目标不变，序号也要递增。
5. **50ms** 内未收到匹配 ACK，原样重发同一帧，最多重试 3 次。期间不并发发送其他控制命令；恢复后发送最新目标，不补发积压目标。
6. 退出控制前，下发新序号的零速命令并确认 ACK，再关闭串口。

这里的零速命令为 `0,0,0,当前yaw目标`；`0,0,0,0` 还会要求云台回到启动方向。零速仍执行闭环，不是电机断电。

控制模式由 DR16 右拨杆决定：

上位或遥控器掉线使用 UART1（与小电脑通讯）

中位使用 UART6（调试接口可忽略）

下位使用遥控器

切换模式的当轮会清零底盘目标并丢弃已排队命令；切回 UART1 后需继续发送新序号命令。ACK=0 只表示 UART1 命令被协议接受，不表示 UART1 正在控制底盘。其他控制模式下，UART1 仍周期回传当前测量值。

发送的是字节，例如 `A5 5A` 表示两个字节，不能发送字符串 `"A5 5A"` 或 `"1,0,0,0"`。不追加回车换行或 JustFloat 帧尾。UART6 保留 VOFA 调试及其中位控制功能。

## 2. 通用帧格式

```text
A5 5A | VERSION | TYPE | SEQUENCE | LENGTH | PAYLOAD | CRC16
 2字节    1字节    1字节    2字节      2字节     N字节    2字节
```

| 字段 | 字节偏移（从0开始） | 类型及含义 |
|---|---:|---|
| 帧头 | 0 | 固定 `A5 5A` |
| VERSION | 2 | uint8，当前为 `01` |
| TYPE | 3 | uint8，见下表 |
| SEQUENCE | 4 | uint16，小端序 |
| LENGTH | 6 | uint16，小端序，仅计算数据区字节数 N |
| PAYLOAD | 8 | N 字节 |
| CRC16 | 8+N | uint16，小端序 |

总长度为 **N+10** 字节。N 最大 64，最大帧长 74。`10 00` 表示数据区长 16 字节。

| TYPE | 方向 | 数据区 | 总帧长 |
|---|---|---|---:|
| `0x01` 控制 | 小电脑 → MCU | 四个 float32，16字节 | 26 |
| `0x80` ACK | MCU → 小电脑 | 一个 uint8 状态码 | 11 |
| `0x81` 状态 | MCU → 小电脑 | 车体 vy、vx、rot 推算值及云台实测角，四个 float32 | 26 |
| `0x02` 参数设置 | 小电脑 → MCU | 预留，当前不支持 | — |

其他请求类型返回 ACK=3。MCU 收到 `0x80`、`0x81` 时直接忽略，不产生应答。

### CRC16

使用 **CRC16/MODBUS**：初始值 `0xFFFF`，右移多项式 `0xA001`，RefIn/RefOut=true，XorOut=0。

- 计算范围：从 VERSION 到 PAYLOAD 末尾，即 `frame[2 : 8+N]`，共 `6+N` 字节。
- 不包含帧头和 CRC 自身；结果低字节先发送。
- 标准校验：ASCII `123456789` → `0x4B37` → 字节 `37 4B`。
- CRC 错误、长度超过64或帧未收齐：不执行、不应答。

## 3. 四个控制值与状态值

控制帧和状态帧的数据区布局相同，顺序固定为 **vy、vx、rot、yaw_angle**，但数据来源和坐标系不同。

### 3.1 控制帧 `0x01`：云台坐标系目标

| 名称 | 数据区偏移 | 含义及单位 |
|---|---:|---|
| vy | 0 | 云台坐标系前后目标速度，m/s；正值沿云台指向前进 |
| vx | 4 | 云台坐标系左右目标速度，m/s；正值向云台右侧 |
| rot | 8 | 底盘旋转目标角速度，rad/s；正方向沿用当前四轮同向正转约定，逆时针为正 |
| yaw_angle | 12 | 云台目标角度，单位度；启动朝向为0°，正方向沿惯导 yaw 定义 |

`1,0,0,0` 表示前进目标1m/s，`0,1,0,0` 表示横移目标1m/s，`0,0,1,0` 表示原地旋转目标1rad/s。它们是控制目标；实际车速需结合反馈与实测距离、周期判断。

惯导安装在云台上。yaw 目标按 `remainder(angle, 360)` 归一化到约 ±180°，例如450°→90°，270°→−90°，按最短角差控制。

四个值均须为有限的 float32，拒绝 NaN、±Inf。协议未规定速度数值上限；完整命令通过校验后，四个目标在控制任务中一起更新。

### 3.2 状态帧 `0x81`：底盘坐标系轮速推算值及云台实测角

| 名称 | 数据区偏移 | 含义及单位 |
|---|---:|---|
| vy | 0 | 四轮实测转速反解的底盘前后速度，m/s；正值沿底盘 +Y |
| vx | 4 | 四轮实测转速反解的底盘左右速度，m/s；正值沿底盘 +X |
| rot | 8 | 四轮实测转速反解的底盘旋转角速度，rad/s；正方向与控制 rot 一致 |
| yaw_angle | 12 | 惯导实测云台角，相对控制任务启动朝向，单位度，约 ±180°；不是目标角，也不是云台相对底盘的编码器角度 |

设 `wLU、wRU、wRD、wLD` 为 LU(3)、RU(2)、RD(1)、LD(4) 的输出轴实测角速度，单位rad/s。令 `A=1/(sqrt(2)*r)`、`B=R/r`，则：

```text
vy  = (wLU - wRU - wRD + wLD) / (4*A)
vx  = (wLU + wRU - wRD - wLD) / (4*A)
rot = (wLU + wRU + wRD + wLD) / (4*B)
yaw_angle = remainder(惯导累计yaw - 启动参考yaw, 2*pi) * 180/pi
```

三项速度使用实测轮速快照，不使用四轮目标轮速，也不使用云台陀螺仪角速度推算底盘转速。轮速推算基于当前几何参数和理想滚动条件，会受打滑、悬空、轮径及传动误差影响，不等于独立测得的对地速度。

下发平移值属于云台坐标系，回传平移值属于底盘坐标系。两者只有在云台与底盘坐标对齐且跟踪正常时才接近。令 `a=云台编码器角度-6.19rad`，理想跟踪时有：

```text
vx_body = vx_command*cos(a) - vy_command*sin(a)
vy_body = vx_command*sin(a) + vy_command*cos(a)
```

状态帧每约10ms发送一次，需按以下规则处理：

- 任一轮从未上线、反馈超过100ms或转速数值非有限时，`vy/vx/rot` 三项均为 **NaN**，表示无法进行完整四轮解算；不能将 NaN 当作0或继续累计里程。恢复四轮有效反馈后自动恢复速度推算。
- yaw 字段独立取自惯导。yaw 电机编码器离线不会将有效的四轮速度推算强制清零；电机输出被禁止时，轮子仍可能滑行。此帧不携带惯导更新时间或电机在线位图；UART6 通道10可查看电机在线情况。
- 序号为最近接受的 UART1 控制命令序号；从未接受过时为 `0xFFFF`。状态帧连续使用同一序号是正常现象。
- 序号只用于命令同步，不表示测量值由该命令产生，也不能表示当前控制模式；UART6 或遥控器控制时仍回传当前测量值。
- 控制层要求 yaw 电机反馈在线；yaw 反馈超时100ms会禁止整个底盘输出，轮子反馈超时100ms会禁止对应轮子的输出。ACK 成功不代表电机已运动。

## 4. ACK 与序号规则

ACK 复制请求的序号，数据区只有一个状态码。小电脑只处理与当前等待序号匹配的 ACK。

| 状态码 | 含义 | 小电脑处理 |
|---:|---|---|
| 0 | 新控制命令已接受 | 结束等待，准备下一序号 |
| 1 | 最近命令的重复帧，已接受过 | 结束等待；不表示当前运动仍有效 |
| 2 | 控制数据长度错误或存在非法浮点数 | 修正数据后重发 |
| 3 | 消息类型不支持 | 使用 `0x01` 控制类型 |
| 4 | 与最近序号相同，但原始数据区不同 | 不再复用该序号，读取状态重新同步 |
| 5 | 版本不支持 | 使用版本 `0x01` |
| 6 | 旧序号 | 读取状态重新同步 |

只有 ACK=0 会更新目标、最近序号及控制超时计时。错误 ACK 仍使用版本1；校验顺序为版本→类型→控制长度/数值→序号。

序号为 uint16，`65535` 的下一个是 `0`。已有最近接受序号 last 时：

```text
delta = (收到的序号 - last) & 0xFFFF
```

| delta | MCU 行为 |
|---|---|
| 0，原始16字节数据区相同 | ACK=1，不重复更新目标 |
| 0，原始数据区不同 | ACK=4，拒绝 |
| 1～32767 | 按新命令接受 |
| 32768～65535 | ACK=6，拒绝 |

首次合法控制可使用任意序号，但客户端统一按“状态序号+1”同步即可。去重按原始字节比较，0°与360°不能用同一序号替换。去重记录不跨 MCU 重启保存；连接、重连或收到 ACK=6 后，都应重新读取状态同步。

## 5. 持续控制与超时

**从接受第一条 UART1 控制命令开始，300ms 未接受新命令，UART1 的 vy、vx、rot 候选目标归零，保留 yaw 目标。** 仅当 UART1 被选中时才影响底盘目标，不会清零 UART6 或遥控器模式的运动目标。

重复帧、错误帧和未知类型均不刷新这个计时器。超时后仍保留最近序号和原始命令；重发旧帧只返回 ACK=1，不恢复运动，必须发送新序号才能恢复。状态帧始终回传轮速推算值和惯导实测角，不会因超时而立即把反馈强制改为0；减速、滑行期间反馈可以非零。

例如持续发送 `1,0,0,0`，应使用序号 `S+1、S+2、S+3…`，各帧重新计算 CRC。串口助手“循环发送同一帧”只能产生一次有效控制，300ms 后仍会归零。

## 6. 流式接收要求

一次串口 read 可能只有半帧，也可能包含多帧。ACK 和状态共用接收流，须按 TYPE 分流，不能使用文本 readline 或 JustFloat 解码。

1. 缓存接收字节，搜索帧头 `A5 5A`；未找到时只保留末尾可能存在的单字节 `A5`。
2. 至少有8字节才读取 LENGTH。长度超过64，丢弃当前起点的一个字节并重新搜索。
3. 等待 `N+10` 字节收齐，再验证 CRC。失败同样只丢弃起点的一个字节，保留后续数据用于重同步。
4. 校验正确后取出整帧，继续处理缓存中的下一帧。数据区允许包含帧头及任意字节，不转义、不提前截断。
5. 未完成帧的相邻接收间隔超过100ms，丢弃残帧。启动日志等非协议内容按帧头和 CRC 过滤。

## 7. 联调用例

以下十六进制帧均已校验 CRC。控制及ACK示例假设 MCU 刚启动，状态序号为 `FFFF`，然后依次发送序号0、1、2，期间没有其他控制命令。实际接入须读取状态同步序号，不能固定照抄示例序号。周期状态帧仅演示给定测量值的编码，实车状态随传感器变化，不能要求与示例逐字节相等。

### A. 前进：`1,0,0,0`，序号0

小电脑发送（26字节）：

```hex
A5 5A 01 01 00 00 10 00 00 00 80 3F 00 00 00 00 00 00 00 00 00 00 00 00 4B 6C
```

MCU 成功应答（11字节）：

```hex
A5 5A 01 80 00 00 01 00 00 45 C0
```

MCU 周期状态编码示例（26字节，假设解算及惯导测量值恰为 `1,0,0,0`）：

```hex
A5 5A 01 81 00 00 10 00 00 00 80 3F 00 00 00 00 00 00 00 00 00 00 00 00 D4 A4
```

### B. 小陀螺：`0,0,3,0`，序号1

小电脑发送：

```hex
A5 5A 01 01 01 00 10 00 00 00 00 00 00 00 00 00 00 00 40 40 00 00 00 00 AD 0D
```

MCU 成功应答：

```hex
A5 5A 01 80 01 00 01 00 00 78 00
```

MCU 周期状态编码示例（假设轮速推算 rot 恰为3rad/s、其余测量值为0；实际不保证达到目标）：

```hex
A5 5A 01 81 01 00 10 00 00 00 00 00 00 00 00 00 00 00 40 40 00 00 00 00 32 C5
```

### C. 停止：`0,0,0,0`，序号2

小电脑发送：

```hex
A5 5A 01 01 02 00 10 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 E6 31
```

MCU 成功应答：

```hex
A5 5A 01 80 02 00 01 00 00 3C 00
```

之后状态帧序号为2；三个速度目标为0，云台目标为启动方向。状态数据反映实际轮速及云台角度，减速和角度收敛期间不要求四项为0。

### D. 异常与超时验收

各行独立从“用例B已接受、最近序号为1”的状态开始测试。

| 操作 | 预期结果 |
|---|---|
| 原样重发用例B | ACK=1，序号1，不刷新300ms计时 |
| 序号仍为1，但改为四个0并重算CRC | ACK=4，目标不变 |
| 重发用例A（序号0） | ACK=6，目标不变 |
| 修改用例B的CRC任意一位 | 无ACK，目标和最近序号不变 |
| 将一帧拆为8字节和18字节，两段间隔小于100ms | 拼成完整帧后处理；未收齐前无ACK |
| 停止下发新命令超过300ms | UART1 模式下底盘目标归零，yaw目标仍为0°；状态序号为1，反馈随实测轮速及惯导角变化 |
| 超时后原样重发用例B | ACK=1，不恢复旋转目标；状态继续回传测量值 |
| 超时后用新序号2发送 `0,0,3,0` | ACK=0，恢复小陀螺目标 |
| 将任一轮反馈中断超过100ms | 三项状态速度均为NaN；yaw仍独立取惯导值 |
| 在UART6或遥控器模式读取UART1状态 | 回传当前轮速推算速度和惯导角，不回显未被选中的UART1目标 |

## 8. Python 组帧参考

下面代码可直接生成控制帧，不自行打开串口或发送运动命令。实际写串口使用 `uart.write(packet)`；接收侧按第6节校验并提取状态帧后，调用 `decode_state_payload(payload)`。字段布局仍为 `'<4f'`，但解码结果属于测量值。

```python
import math
import struct


def crc16_modbus(data):
    crc = 0xFFFF
    for byte in data:
        crc ^= byte
        for _ in range(8):
            crc = (crc >> 1) ^ (0xA001 if crc & 1 else 0)
    return crc


def make_control(sequence, vy, vx, rot, yaw_angle):
    values = (vy, vx, rot, yaw_angle)
    if not 0 <= sequence <= 0xFFFF:
        raise ValueError('sequence must be uint16')
    if not all(math.isfinite(v) for v in values):
        raise ValueError('control values must be finite')
    payload = struct.pack('<4f', *values)
    if not all(math.isfinite(v) for v in struct.unpack('<4f', payload)):
        raise ValueError('values must fit finite float32')
    body = struct.pack('<BBHH', 1, 0x01, sequence, len(payload)) + payload
    return b'\xA5\x5A' + body + struct.pack('<H', crc16_modbus(body))


def decode_state_payload(payload):
    if len(payload) != 16:
        raise ValueError('state payload must be 16 bytes')
    vy_body, vx_body, rot_body, yaw_actual_deg = struct.unpack('<4f', payload)
    return {
        'vy_body_mps': vy_body,
        'vx_body_mps': vx_body,
        'rot_body_radps': rot_body,
        'yaw_actual_deg': yaw_actual_deg,
        'velocity_valid': all(math.isfinite(v) for v in (vy_body, vx_body, rot_body)),
        'yaw_valid': math.isfinite(yaw_actual_deg),
    }


assert crc16_modbus(b'123456789') == 0x4B37
packet = make_control(1, 0, 0, 3, 0)  # 对应用例B
print(packet.hex(' ').upper())
```

持续控制的客户端逻辑：

```text
连接 → 收状态S → sequence=(S+1)&0xFFFF
循环：
    取当前四个目标，生成并保存本帧
    发送本帧，等待匹配ACK（等待期间继续处理状态帧）
    50ms无ACK → 原样重发，最多3次；仍失败则退出运动控制并重连同步
    ACK=0或1 → sequence=(sequence+1)&0xFFFF，按约20ms周期发送最新目标
    ACK=2～6 → 按第4节处理，不当作成功，不无限重发错误命令
停止：UART1模式下用新序号下发零速目标 → 确认ACK → 检查有效速度反馈在合理容差内收敛至0 → 关闭串口
```

客户端应分别保存“下发目标”和“状态测量值”，不要用回传的实测 yaw 覆盖仍希望保持的 yaw 目标。旧版 `uart1_com10_smoke.ps1` 按“状态等于目标”验收，已不适合直接验证新版状态语义；本次未修改或运行该实车脚本。
